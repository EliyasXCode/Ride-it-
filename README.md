# RideFlow — Urban Ride-Booking Web Application

RideFlow is a production-grade, full-stack ride-booking web application inspired by Uber’s core booking experience. Built with a TypeScript monorepo architecture featuring an emerald (#10b981) accent on clean white and charcoal surfaces.

---

## 1. Quick Start & Development Commands

### Prerequisites
- Node.js 18+ or 20+
- npm 9+
- (Optional) Local MongoDB or MongoDB Atlas connection URI

### Step 1: Install Dependencies
```bash
# In the root rideflow/ directory:
npm install
```

### Step 2: Configure Environment Files
RideFlow comes with `.env.example` templates in both `apps/api` and `apps/web`:
- `apps/api/.env` (Backend port, MongoDB URI, Google Maps Server Key, Gemini Key, Stripe Sandbox)
- `apps/web/.env.local` (Browser Google Maps Key, API target)

### Step 3: Seed Demo Accounts (Idempotent)
```bash
# Seed initial test rider and approved driver
npm run seed --workspace=apps/api

# Bootstrap the administrator account
npm run seed:admin --workspace=apps/api
```

### Step 4: Run Application
```bash
# Run both backend API and frontend Next.js concurrently:
npm run dev

# Or run individually:
npm run dev --workspace=apps/api  # Running on http://localhost:5000
npm run dev --workspace=apps/web  # Running on http://localhost:3000
```

## 4. Key Engineering Implementations

### A. Authoritative Ride State Machine
$$\text{requested} \longrightarrow \text{searching} \longrightarrow \text{assigned} \longrightarrow \text{arriving} \longrightarrow \text{arrived} \longrightarrow \text{in\_progress} \longrightarrow \text{completed}$$
- Atomic database updates prevent race conditions (two drivers accepting the same ride).
- Driver offers dispatch in controlled 15-second windows with retry limits and automated fallback.

### B. Mandatory 4-Digit Ride-Start PIN
- Before a trip starts, the rider provides a 4-digit PIN generated by the backend.
- The driver must submit this PIN through their interface; the backend verifies the code with attempt limits (maximum 3 attempts) to prevent vehicle mismatches.

### C. Gemini AI Assistant (Official `@google/genai` SDK)
- Backend-only integration reading `GEMINI_API_KEY` and `GEMINI_MODEL` (`gemini-2.5-flash`).
- Parses unstructured natural language requests (e.g. *"I need a ride from Union Square to the airport tomorrow"*) into structured form parameters.
- Answers FAQs, vehicle differences, and pricing formulas without hallucinating coordinates or fares.

### D. Google Maps & Cost Control
- Separate client-side browser key (`NEXT_PUBLIC_GOOGLE_MAPS_API_KEY`) and server routing key (`GOOGLE_MAPS_SERVER_API_KEY`).
- Places queries are debounced with minimal field masks.
- Full `DEMO_MODE` and vector canvas fallback when keys are restricted or offline.

## 6. Known Limitations & Production Readiness

1. **SMS / Phone Masking**: Current notifications are delivered via WebSockets and in-app banners. Production deployment requires Twilio integration for phone number masking.
2. **Automated Driver Payouts**: Driver earnings are recorded in a calculated accounting ledger. Live bank transfers require Stripe Connect Custom or Express onboarding.
3. **Continuous Background Tracking**: Mobile browsers pause JavaScript geolocation when the device screen locks or the tab is backgrounded. Native mobile apps (React Native / Flutter) are recommended for uninterrupted driver tracking.
